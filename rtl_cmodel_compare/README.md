# RTL vs C Model Verification

This directory is an automated replacement for the old manual flow where
C-model dumps were copied into an RTL `data/` directory by hand. It keeps all
new verification code and generated outputs outside `cmodel/` and `rtl/`.

## What It Does

The flow:

1. Builds the C model from `../cmodel/necessary_source/all_fmac_test.cu`.
2. Runs the C model with `--dtype`, `--seed`, and `--vec-count`.
3. Converts C-model dumps into the same text-file style used by the old TB.
4. Builds `../rtl/fpe/rtl/top.sv` with Verilator.
5. Drives the RTL and compares `D_bits_o` against the C-model golden output.

The golden output is generated by the custom C model only. This flow compiles
the C model with `-DNVIDIA_ON=0` using `c++`, so it does not call NVIDIA MMA
instructions and does not require CUDA/GPU support.

The RTL source path is discovered from:

```text
../rtl/fpe/rtl
```

If you edit RTL in the per-pipe directories such as `../rtl/pipe4`, sync it into
the flattened compile directory before simulation:

```bash
cd ..
python3 rtl/sync_pipe_to_fpe.py --check
python3 rtl/sync_pipe_to_fpe.py --apply
```

From this directory, the same commands are available as:

```bash
make check-rtl-sync
make sync-rtl
```

`make run`, `make sim`, and `make debug-mismatch` run `make check-rtl-sync`
before compiling, so stale `../rtl/fpe/rtl` code is caught before simulation.

## Quick Start

From the repository root:

```bash
cd rtl_cmodel_compare
make run DTYPE=1 VEC_COUNT=100 SEED=1
```

Fast check across all currently supported non-scale dtypes:

```bash
make smoke SMOKE_COUNT=2 SEED=1
```

Larger regression:

```bash
make regress REGRESS_COUNT=100 SEED=1
```

Run selected dtypes in order and stop on the first mismatch:

```bash
make run-dtypes DTYPES="1 2 3 11 12" VEC_COUNT=1000 SEED=1
```

`RTL_BITSIZE` defaults to the `ReduceWidth` value in `../rtl/fpe/rtl/defines.sv`,
and `CMODE_BITSIZE` defaults to the same value. You can override them explicitly:

```bash
make run DTYPE=11 VEC_COUNT=10 SEED=1 CMODE_BITSIZE=512 RTL_BITSIZE=512
make run DTYPE=9  VEC_COUNT=10 SEED=1 CMODE_BITSIZE=256 RTL_BITSIZE=256
```

Find the first mismatch in a large random run, then replay only that vector:

```bash
make debug-mismatch DTYPE=3 VEC_COUNT=1000000 BATCH_COUNT=100000 SEED=1
```

Run the same debug-mismatch search across multiple dtypes in order. The flow
stops as soon as any dtype finds a mismatch, and `mismatch_debug/` keeps that
failing vector's waveform and C-model trace:

```bash
make debug-mismatch-dtypes DTYPES="1 2 3 11 12" VEC_COUNT=1000000 BATCH_COUNT=100000 SEED=1
```

Supported dtypes:

```text
0  I8I8I32
1  F16F16F32
2  BF16BF16F32
3  TF32TF32F32
4  I8U8I32
5  U8I8I32
6  U8U8I32
7  MXFP8E4M3F32
8  MXFP8E5M2F32
9  NVFP4F32
10 MXFP4F32
11 FP8E4M3F32
12 FP8E5M2F32
13 MXFP6E3M2F32
14 MXFP6E2M3F32
15 I4I4I32
16 I4U4I32
17 U4I4I32
18 U4U4I32
```

For `DTYPE=11/12`, the RTL opcode remains `11/12`, but the C model is run with
its internal mixed-float dtype ids `32/38`. The C-model FP8 payload follows
`CMODE_BITSIZE`: 512-bit generates 64 bytes per vector, while 256-bit generates
32 bytes per vector.

For `DTYPE=7/8/13/14`, the RTL opcode remains `7/8/13/14`, while the C model is
run with its internal scaled mixed-float dtype ids `57/63/75/69`. The data
payload follows `CMODE_BITSIZE`. One scale byte is generated per 32 input
elements; for 512-bit runs, the two C-model scale bytes are packed into the low
RTL raw scale slots in block order.

For `DTYPE=9`, NVFP4 retains one scale byte per 8 payload bytes. `DTYPE=10`
(MXFP4) and `DTYPE=19` (MXINT4) use one external scale byte per 32 four-bit
elements: a 256-bit payload therefore writes two A scales and two B scales.
Before CModel/NVIDIA execution, those two values are expanded to the four
16-element slots as `[s0, s0, s1, s1]`. For RTL comparison the two bytes occupy
the low raw scale slots and all remaining scale-bus bits are zero. The flow
builds the C model with `NVIDIA_ON=0`, so MXINT4 is compared against the custom
CModel rather than a native NVIDIA MMA instruction.

For `DTYPE=15-18`, the C model and RTL use packed low-nibble-first S4/U4
payloads. `INT4_K` defaults to `RTL_BITSIZE / 4`, so a 512-bit input compares
128 signed/unsigned 4-bit products. The flow passes this value to the C model
as `--int4-k` and uses its `_k<INT4_K>` dump-file suffix automatically. For
example:

```bash
make run DTYPE=16 VEC_COUNT=100 SEED=1
make run-dtypes DTYPES="15 16 17 18" VEC_COUNT=100 SEED=1
```

## Generated Files

Each run creates:

```text
runs/dtype_<dtype>_seed_<seed>_count_<count>/
```

Important files inside that run directory:

```text
vectors/A.txt         RTL-width A input per vector, old TB-compatible name
vectors/B.txt         RTL-width B input per vector
vectors/C.txt         32-bit C input per vector
vectors/A_scale.txt   A scale input, zero for non-scale dtypes
vectors/B_scale.txt   B scale input, zero for non-scale dtypes
vectors/D.txt         32-bit C-model golden output
vectors/metadata.json exact C-model source dump paths and dtype metadata
fail_log.txt          mismatch log written by the SystemVerilog TB
tb_top.fst            waveform only when DUMP_WAVE=1, normally the single failure vector from debug-mismatch
```

The shared Verilator build lives under:

```text
build/verilator_trace_0/
build/verilator_trace_1/
```

So changing `SEED` or `VEC_COUNT` does not rebuild the RTL simulator unless the
RTL or testbench source changes.

## Debug Commands

Stop at the first mismatch, which is the default:

```bash
make run DTYPE=1 VEC_COUNT=100 SEED=1
```

For large random testing, prefer this command:

```bash
make debug-mismatch DTYPE=3 VEC_COUNT=1000000 BATCH_COUNT=100000 SEED=1
```

It searches without waveform, stops at the first mismatch, then uses the saved
search inputs to replay only that vector with `TRACE=1 TRACE_DETAIL=0
DUMP_WAVE=1`. It also replays those exact saved inputs through the C model with
intermediate tracing enabled. This avoids regenerating a different random
payload during replay. All files are overwritten on the next `debug-mismatch`
run:

```text
mismatch_debug/first_mismatch.txt  first failing vector and got/expected values
mismatch_debug/search/             last no-wave search batch
mismatch_debug/wave/               single-vector replay with tb_top.fst
mismatch_debug/cmodel_trace/       C-model trace run for the same failing vector
```

For the no-wave search batch, the script automatically uses at least
`BATCH_COUNT + TIMEOUT_CYCLES` as the simulator timeout. If a search batch fails
before writing a mismatch entry, inspect:

```text
mismatch_debug/search/run.log
```

Open the replay waveform:

```bash
surfer mismatch_debug/wave/tb_top.fst
```

Inspect the C-model trace:

```bash
ls mismatch_debug/cmodel_trace/cmode_trace
cat mismatch_debug/cmodel_trace/cmode_trace/mant_align_*_to_*.txt.log
cat mismatch_debug/cmodel_trace/cmode_trace/mant_sum_*_to_*.txt.log
```

Keep going after mismatches and collect a longer `fail_log.txt`:

```bash
make run DTYPE=1 VEC_COUNT=100 SEED=1 STOP_ON_FAIL=0
```

Allow a small FP32 ULP tolerance:

```bash
make run DTYPE=1 VEC_COUNT=100 SEED=1 ULP_TOLERANCE=1
```

Re-run only vector generation:

```bash
make vectors DTYPE=1 VEC_COUNT=100 SEED=1
```

Build only the RTL simulator:

```bash
make sim
```

Remove generated artifacts:

```bash
make clean
```

## 512-bit Check

The current C-model setting:

```cpp
int bitsize = 8 * 64;
```

matches the RTL interface:

```systemverilog
`define ReduceWidth 512
```

For dtypes `0-6`, each vector contains:

```text
int8:  64 A bytes + 64 B bytes
fp16:  32 A elements + 32 B elements
bf16:  32 A elements + 32 B elements
tf32:  16 A elements + 16 B elements
c/d:   one 32-bit value
```

Do not use `TOPOLOGY_128_INPUT=1` for this 512-bit RTL comparison unless you
also intentionally want topology-adapted 128-bit C-model input.
